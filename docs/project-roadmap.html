Where We Are

  • Core flows are functional, but some UI behavior, persistence details, and shell/runtime overlap still need hardening.
  • The priority is making the migrated app feel complete, consistent, and reliable rather than expanding broad new feature scope.
  • Legacy fallback still exists as a safety net, which means the desktop shell is not yet the unquestioned default experience.

Where We Are Going

  • Finish migration-recovery work until the current desktop runtime is clearly the primary experience.
  • Use pre-beta hardening to reduce overlap, fix regressions, and keep large files refactored while stabilizing behavior.
  • Enter beta only once daily-use workflows are reliable enough that the legacy fallback is optional instead of necessary.

Beta Means

  • Feature-complete for normal daily use.
  • Legacy fallback is optional instead of required.
  • Remaining issues are mostly edge cases or polish.

Near-Term Tasks

  • Keep shrinking legacy bootstrap/runtime responsibilities once migrated replacements are proven.
  • Review large files during normal work and split them into feature-folder modules early.
  • Verify installer, protocol handling, persistence, and resource-download flows after major changes.
  • Treat restart-only, resize-only, and manual-interaction-only bugs as high-priority stabilization issues.

Stable Means

  • Default recommended experience.
  • No major workflow depends on legacy fallback.
  • Reliability and persistence are strong enough that updates are incremental, not recovery-oriented.

  • Stabilization fixes
  • Structural cleanup and continuous refactoring
  • Parity improvements where the historical UX still matters
  • UX polish and consistency
  • Only then broader feature expansion
